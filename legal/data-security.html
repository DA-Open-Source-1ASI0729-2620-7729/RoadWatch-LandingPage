SECURITY

Data Security

Last updated: September 2026

RoadWatch is designed to support secure handling of environmental telemetry, project records, and compliance information. This page summarizes the security principles applied to the platform.

1. Security Approach

RoadWatch is designed around defense-in-depth principles, combining access control, encryption, monitoring, and secure development practices to protect platform and project data.

2. Encryption

Data should be protected in transit using modern TLS encryption. Sensitive stored information should use appropriate encryption-at-rest controls provided by the hosting and database environment.

3. Authentication and Access

Access to RoadWatch should follow least-privilege principles. Administrative and sensitive functions should be restricted to authorized users and protected with strong authentication controls.

4. Auditability and Integrity

RoadWatch may use cryptographic hashes, timestamps, logging, and traceability controls to help preserve the integrity of environmental records, reports, and evidentiary data.

5. Secure Development

Security practices may include dependency updates, code review, environment separation, secure configuration, backup procedures, and vulnerability remediation.

6. Incident Response

Potential security incidents should be investigated promptly. Where required, affected customers and relevant authorities should be notified in accordance with applicable contractual and legal obligations.

7. Customer Responsibilities

Customers are responsible for safeguarding credentials, assigning appropriate permissions, maintaining secure endpoints, and reporting suspected unauthorized access as soon as possible.

8. Security Contact

Security-related questions or reports may be sent to support@roadwatch.com.
